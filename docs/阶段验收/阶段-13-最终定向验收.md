## 1. 公交参考的日期有效性：通过

| 检查 | 实际结果与证据 |
|---|---|
| 修改旅行需求日期 | `saveRequestDraft` 清除需求的确认版本、确认时间和确认内容；原计划标为需求待更新，事件及公交参考仍绑定原计划的日期快照，不自动改标为新日期。新增[服务回归](../../tests/manual-route-service.test.ts)覆盖完整过程。 |
| 按新日期生成计划 | 已确认地点属于受保护事实，单改需求不能绕过保护而替换原计划。测试先验证生成被拒绝，再通过既有地点编辑入口明确取消地点确认，生成新日期计划；新计划无旧路线、无旧路线费用。再次保存人工参考必须重新勾选核对；服务端从当前事件取得日期，不接受客户端伪造日期。 |
| 切换地图日期 | 新增[浏览器用例](../../tests/e2e/manual-transit.spec.ts)先勾选第一天、切到第二天，验证勾选清除、第二天显示自己的适用日期、表单不带第一天线路、保存禁用；再切回第一天，原已保存参考仍保留，但核对勾选再次清除。第二天未保存草稿不修改第一天记录。 |
| 改出发时刻 | 既有浏览器测试验证清除核对勾选、保存禁用、保留未保存文字/金额/耗时；旧摘要标明不适用于当前选择，继续显示原适用时刻。重新核对并保存后生成新版本。 |
| 改起终点或相关日程 | 既有服务测试验证地点改变、事件改时刻使参考 `requiresReconfirmation=true`，派生耗时、到达和估计金额清空。原人工日期、时刻、线路保留供核对；不相邻的旧路线退出当前版本。浏览器验证失效提示及未勾选状态。 |
| 历史版本 | 新日期/新时刻保存不改旧版日期、线路和费用；历史表单只读。保存入口有版本及事务内相邻关系复核。 |

实现证据：[日期与表单身份](../../app/components/plan-map.tsx)、[核对状态](../../app/components/manual-transit-form.tsx)、[原适用日期与失效展示](../../app/components/route-summary.tsx)、[失效字段](../../lib/routes.ts)、[服务端保存](../../lib/route-service.ts)。

测试结果：人工路线服务文件 **8/8** 用例纳入全量通过；人工公交浏览器文件 **9/9** 用例通过。日期新增用例各 1 项，既有时刻、地点与失效测试未重复改写。

未验证/不适用：现有产品没有直接修改单个事件“开始日期”的界面或 API；`endDate` 用于跨午夜。此次核实的是实际存在的需求改日期、生成新日期计划、地图切换日期及事件改时刻链路，没有新增日期编辑功能。修改需求日期不会销毁旧快照的历史核对依据；它也不会使旧参考适用于新日期。人工记录始终为待确认，没有真实运营保证。

## 2. 预算与历史版本：通过

## 3. 正式数据隔离：修复后通过

本项直接检查了连接创建、测试初始化、删除边界和当前运行服务，并执行回归及文件指纹对比，没有依赖先前总结报告推定通过。

发现并最小修复的缺口：

1. `route-cost.test.ts` 原先在设置测试路径前静态导入持有 Prisma 客户端的服务。改为先设置并检查隔离目录，再动态导入，结束时关闭连接。原测试使用纯计算函数，没有据此认定曾写入正式库。
2. 测试清理只有词法路径判断，不能排除 Windows junction、符号链接或硬链接。新增[路径守卫](../../scripts/test-data-safety.mjs)，限制为项目 `test-data` 的真子目录，逐层检查祖先及真实路径；清理前检查整棵目标目录，拒绝链接。已接入[清理脚本](../../scripts/clean-test-data.mjs)及[测试库工具](../../tests/helpers/test-database.ts)。人工公交服务测试也复用该工具，移除自己的无链接防护的创建/清理流程。
3. 两个阶段 13 演示脚本原来只固定 3121 端口和演示库路径，未证明它们是同一实例。新增[同库校验](../../scripts/verify-isolated-server.mjs)：只在经过路径检查的演示库创建随机临时标记，经回环服务的只读 GET 验证同一标记，成功后才允许浏览器操作。错误库、非回环地址、内容不符和重定向均拒绝；无论成功或失败，只清理自己的精确标记。未新增产品 API。

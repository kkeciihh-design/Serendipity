- `npm run typecheck`、`npm run lint`、`npm run build` 均通过：[类型](证据/阶段-16/typecheck.log)、[静态](证据/阶段-16/lint.log)、[构建](证据/阶段-16/build.log)。最终正式和演示实例已加载该生产构建。
- 完整浏览器回归 `npx playwright test --workers=1`：**64项通过**，[日志](证据/阶段-16/browser-all.log)。随后补强OCR进程清理，最终构建下本阶段5项全部复测通过；新增真实识别与手工红线完整对照后，该闭环单独再通过，[复测](证据/阶段-16/browser-final.log)、[对照](证据/阶段-16/browser-ocr-comparison.log)。没有忽略失败项。
- 实际检查390 / 768 / 1440px，无横向溢出，裁剪、输入、预览和按钮可用，并查看三种尺寸的图片：[手机](证据/阶段-16/crop-panel-390.png)、[平板](证据/阶段-16/crop-panel-768.png)、[桌面](证据/阶段-16/crop-panel-1440.png)。完整页面截图及演示重开截图在同一证据目录。
- 旧功能回归包含手工火车 / 航班、草稿转有效、历史只读、同行退改、预算付款 / 退款、需求修订、地图 / 路线、红线、权限、设置、旅行保存等。`npm audit --omit=dev` 无已知漏洞，`git diff --check` 无错误。

实际修复过的问题：文本清理把站名后的换行合并，导致“长沙南出发”；退改种类判断未处理OCR词间空格；Tesseract对象语言加载路径失败；指定原票下拉框缺明确无障碍标签；Next默认请求缓冲无法容纳10MB图片的Base64。均已修复并复测。最后发现库在模型初始化失败时可能不返回Worker，改为可由父进程强制结束的短生命进程，新增取消 / 超时 / 失败 / 限流测试，并再次真实识别与生产网页验证。

真实能力：Tesseract本机CPU OCR，中文与票面数字 / 拉丁车次，实际验证日期和结果见JSON；未调用外部云OCR / 付费视觉服务。模拟仅用于数据库提交失败、路线离线、HTTP失败和迟到响应，以及生命周期中的模型加载失败 / 卡住，不将这些模拟当成真实OCR成功。

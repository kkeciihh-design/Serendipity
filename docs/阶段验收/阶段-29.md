## 修复与复测

1. Node fetch未按测试预期发送自定义Host，首轮断言失败；测试改用真实`http.get`指定Host，确认401，应用保护逻辑未放宽。
2. 从Node启动whoami.exe被本机环境以EPERM拒绝。权限验收改为独立PowerShell脚本，通过.NET读取当前SID并设置/恢复隔离目录ACL；真实权限失败和修复成功均已执行。
3. 浏览器测试在客户端路由切换完成前立即计数得到0；改为等待目标标题与URL，整组重跑通过。
4. 静态检查发现新脚本全局名与异常cause问题；修正后ESLint通过。
5. 加入“已初始化数据库缺失时拒绝创建空库”保护，并实测未生成替代数据库。
6. 原生Windows自动化首次观察到全部快捷方式并执行过双击；用户继续任务后，恢复窗口失败，工具返回`failed to activate captured window`。停止该UI自动化路径，最终以Windows ShellExecute实测真实快捷方式、默认浏览器窗口、提示窗口及HTTP状态，不把失败的截图路径计为成功。两次验收产生的已完成提示窗口由脚本只结束其本轮新建的对应PowerShell进程，不结束应用服务。

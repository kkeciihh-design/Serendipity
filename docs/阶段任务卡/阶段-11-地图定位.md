## 4. 本阶段详细规格

### 目标

在真实地图中看到已确认的旅行地点。

### 用户能看到什么

当天地点、城市范围、地图来源及待确认位置。

### 功能要求

接入一个地图服务，搜索/确认地点并准确标点；支持出发点、枢纽、住宿区域、景点和餐厅；跨城概览与城市详图可读。

### 页面

详情地图区、手机地图页签；设置增加地图配置。

### 交互

放大/缩小、拖动地图，搜索并选择准确地点；多候选可消歧，找不到时可保持待确认。

### 数据

经纬度、坐标系、地图 POI ID、地址、区域参考点标识和来源。

### 技术实现

客户端地图组件、受限服务端请求、安全密钥代理；同时验证静态图/导出许可和可用能力。

### 测试

真实地图加载和地点查询；同名不同城、深圳站/深圳北、错 Key、无结果、坐标系转换、手机操作、导出资源探测。

### 验收标准

地点落在正确位置；模糊位置不冒充精确酒店；错误不会清空计划；后期导出有已验证的可行来源。

### 常见失败情况

坐标顺序颠倒、坐标系偏移、浏览器 Key 与服务 Key 混用、未授权空地图。

### Definition of Done

通用 DoD 和真实地图验收通过，记录选型、权限和导出条件。

### 本阶段不做什么

不画伪路线、不做编号联动或专业导航。

## 5. 按这个顺序完成

1. 验证首选地图服务的实际账号能力、坐标体系、安全 Key 用法及静态图/导出用途。
2. 接入真实地图和地点搜索，确认城市、地址与准确站点。
3. 实现当天地点与跨城/城市尺度显示；住宿区域显示为区域参考，不冒充已订酒店。
4. 处理同名、无结果、Key 错误和坐标转换；失败保留文字行程。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

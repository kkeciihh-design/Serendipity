## 4. 本阶段详细规格

### 目标

把旅行方便地复制到微信、备忘录或其他 AI。

### 用户能看到什么

清晰的纯文字/Markdown 内容，可复制或下载。

### 功能要求

包含每日时间、地点、交通、红线、预算、清单和必要来源；保留未核验提示与版本信息。

### 页面

文字预览与导出面板。

### 交互

选择纯文字或 Markdown、复制、下载；复制不可用时允许全选或下载。

### 数据

复用导出快照，只新增格式与生成记录。

### 技术实现

统一格式化函数输出 UTF-8，不重新调用模型；清理不适合文字阅读的界面内容。

### 测试

复制成功/权限拒绝、中文/特殊字符、多天、未知价格、跨日、隐私选项；核对与网页同版本数据。

### 验收标准

文字粘贴后可独立阅读，红线和关键待确认事项不丢，下载编码正确。

### 常见失败情况

只复制概述、来源丢失、金额与网页不一致、按钮失败无反馈。

### Definition of Done

通用 DoD 通过，实际复制和文件读取验证完成。

### 本阶段不做什么

不接微信接口，不自动给别人发送行程。

## 5. 按这个顺序完成

1. 从快照格式化纯文字和Markdown，不重新调用模型。
2. 包含日程、交通、红线、预算、清单和关键来源/待确认项。
3. 实现复制和UTF-8下载，权限拒绝时给可全选文本与下载。
4. 核对中文、特殊字符、跨日、隐私和多天版本一致性。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

## 4. 本阶段详细规格

### 目标

让作者能保留旅行数据，并在升级或换电脑后恢复，恢复前的旧请求不能覆盖恢复后的数据。

### 用户能看到什么

“下载旅行备份”和“从备份恢复”，能预览备份包含多少趟旅行及影响范围；恢复中显示写入暂停，旧页面提示重新载入后再操作。

### 功能要求

一致性备份需求及修订、计划版本及生成依据快照/绑定修订、票面必要字段和有效状态、清单、执行状态与来源；排除密钥、登录会话、原图及运行实例的 dataGeneration/恢复屏障。先校验文件并预览影响，用户确认后建立持久恢复屏障，暂停业务写入，在屏障内制作一致性安全副本再改旅行数据；恢复成功或屏障内失败经保护/回退后，都须持久换代才重新开放写入，管理员和服务配置保留。本阶段起技术恢复/回退也执行同一屏障与换代协议。

### 页面

设置中的数据管理，包含恢复摘要、影响范围和恢复/回退状态；业务写入入口在恢复期间显示暂停原因。

### 交互

下载备份；选择备份后看内容摘要及影响范围，明确确认再恢复；校验失败只给出原因，不进入恢复。恢复期间暂停写入，可保留只读状态展示；成功后重新读取业务状态，旧页面和旧候选不能继续直接提交。失败时先保护原数据或回退，完成恢复处理后再开放操作；未完成时保留可恢复说明。

### 数据

有格式版本的旅行数据备份、恢复记录、恢复前一致性安全副本；持久的运行实例元数据 dataGeneration、恢复屏障及恢复进度。实例元数据不进入旅行备份，也不随网页或技术恢复/回退还原；普通重启保留持久代际，未完成恢复另走恢复处理。页面加载和请求开始时捕获 dataGeneration，它与既有 requestRevision、计划/清单/执行修订共同用于提交检查。

### 技术实现

首版用结构化单文件备份旅行数据，按 Schema 校验；图片许可资料和来源保留，不要求打包所有导出缓存。用普通业务函数和短事务回补全部既有业务写入、生成保存、候选应用、导出登记入口：即使允许只读展示，全部业务提交事务仍须重新检查恢复屏障、捕获的 dataGeneration 及已有业务修订。网页和技术恢复/回退均在屏障持久化后先制作并验证一致性安全副本；成功时在替换旅行数据的同一短事务中换新 dataGeneration 并解除屏障。屏障建立后的失败须先确保原数据完整或回退，再持久换代并解除屏障；保护、回退或换代未完成则保持屏障。进程重启先识别未完成恢复，完成安全恢复或回退并换代后才开放写入，不得直接清屏障；普通重启保留已有代际。拒绝旧请求后必须重读业务状态，不能只补最新代际重发旧载荷；旧候选和在途结果不得作为当前有效结果落盘。外部调用一律在事务外，代际检查不替代已有需求和业务版本检查。

### 测试

正常恢复、空备份、损坏/旧版/恶意内容、恢复中失败、磁盘不足；恢复后核对旅行数、费用、事件、清单、进度与管理员配置。T32：V5 请求在途→恢复 V4→新编辑再次到 V5→旧响应返回，必须因 dataGeneration 不同而拒绝；另测旧页面写入、旧候选应用、旧导出登记、屏障建立时的在途提交，以及安全副本/替换失败和进程中断后恢复或回退的换代边界；技术恢复/回退同样换代，普通重启保留代际。

### 验收标准

失败不覆盖当前数据；恢复能重新打开旅行并重算，管理员和服务配置不被替换；文件不包含服务秘密或实例元数据。恢复屏障覆盖所有业务提交，成功、屏障内失败或进程中断处理后均先持久换代再开放写入；旧请求即使业务版本重新相同也不能覆盖恢复后的数据，旧页面须重读，作者无需操作数据库。

### 常见失败情况

直接替换带密钥的数据库、用导出 PDF 冒充可恢复备份、恢复只剩标题、升级先删库；安全副本完成前仍允许业务提交、dataGeneration 随备份回退、只换最新代际重发旧载荷、失败或重启后未处理恢复屏障就开放写入。

### Definition of Done

通用 DoD 通过，完成一次备份→独立环境恢复→关键数据比对及失败回退；T32 的版本重用、旧页面/候选/导出登记、屏障竞争、失败和进程中断用例通过，技术恢复/回退遵循同一协议，全部既有提交入口已纳入恢复保护。

### 本阶段不做什么

不做云同步、跨设备自动合并、企业灾备和永久票图存储，不为恢复引入队列或复杂锁服务；不以 dataGeneration 替代已有 requestRevision 和计划等业务修订。

## 5. 按这个顺序完成

1. 定义有格式版本的一致性旅行备份，包含必要业务状态、来源、需求修订及计划依据/历史，不含服务密钥/会话/原图或实例元数据；本阶段首次建立持久 dataGeneration 和恢复屏障。
2. 盘点并回补全部既有业务写入、生成、候选应用和导出登记入口；页面/请求捕获代际，提交短事务重新核对屏障、代际及需求/计划/清单/执行修订，不能只给旧载荷补最新代际重试。
3. 实现设置页下载备份、读取摘要、校验及影响预览；用户确认后先持久化恢复屏障、暂停新业务写入，在屏障内制作并验证当前数据的一致性安全副本，再处理旅行数据替换。
4. 成功时在替换旅行数据的同一短事务内换新 dataGeneration 并解除屏障；屏障内失败先保护原数据或回退，再换代解除屏障，管理员和服务配置不受覆盖。保护/回退/换代未完成不得开放写入；外部调用放在事务外。
5. 增加进程启动时未完成恢复的识别和安全恢复/回退路径，持久换代后才开放业务提交；技术恢复/回退使用相同协议，普通重启保留代际，不得直接清屏障。恢复前旧页面、旧候选和在途结果须失效并重新读取业务状态。
6. 在独立测试环境完成恢复并逐项比对，验证损坏/旧版本/空间不足/恶意内容；执行 T32 的 V5→恢复V4→再到V5 旧响应拒绝，以及旧页面/候选/导出登记、失败和中断边界。
7. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
8. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

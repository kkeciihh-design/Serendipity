## 4. 本阶段详细规格

### 目标

省去逐项输入票面信息，确认后自动用于行程计算。

### 用户能看到什么

上传、裁剪、识别预览和确认；加入或确认指定票退票/替换后更新红线，有冲突或资料不足时明确待处理。

### 功能要求

识别日期、车站、车次、出发/到达时刻及座位；关键字段必经确认；处理缺字段、跨日、疑似重复、同行票和替换票；保护原图隐私。复用阶段14的稳定票据身份与有效状态，仅 active 票参与当前约束；退改截图先作为待确认资料，用户确认已办成的退票/替换事实后才更新指定票。保留旧票历史及已支付费用，退款按阶段09规则另行确认；替换单张不影响其他 active 同行票。

### 页面

交通页的导入面板、识别确认页及共用的指定票退票/替换事实确认面板。

### 交互

选图并在发送前裁剪 → 识别 → 修正 → 选择去程/返程、同行票或指定原票的替换 → 用户确认后提交；退票资料也须确认指定原票和已退事实，取消或未确认不修改计划。需求已改未确认时仍可记录用户确认的真实票据/退票与费用事实；有冲突或资料待补时如实保存，不因暂时不可行而改写票面。多人不同班次无法用当前单线表达时保存事实并显示冲突。

### 数据

临时图、识别草稿、复用阶段14的 Ticket（稳定 ticketId、status=draft/active/cancelled/replaced、confirmedAt、可选 replacedByTicketId）、匿名票数/座位信息、识别来源、去重线索；confirmedAt 表示历史确认，不替代当前有效状态。

### 技术实现

真实视觉模型或合规 OCR 适配；上传校验、临时清理，外部调用放在事务外。确认/退票/替换共用阶段14短事务：核对当前计划等适用版本，同步真实票据/费用事实、新计划版本与已引入的约束/事件/路线/时间，并将阶段15红线纳入同次失效重算；替换同时写新票 active、指定旧票 replaced 及 replacedByTicketId，退票只将指定票 cancelled。事实更新继承当前 PlanVersion 的 requestSnapshot/R，需求已改未确认时不冒充采用最新需求，旧计划仍待更新。共享事件依仍 active 的票判断；路线查询失败仍须原子保存已确认事实与旧派生结果失效/待重算或冲突状态，旧路线和红线不得冒充有效；数据库提交失败不留下半更新。

### 测试

T13/T14/T26；模糊/旋转/缺年份/次日到达/退改票、重复截图、同行不同座位、无金额、确认前取消；T30：有效票确认退票、替换指定票、两张同行票只替换一张，核对有效约束、共享事件、费用与红线失效重算；需求已改未确认或路线查询失败时仍记录真实事实并使旧派生结果失效，版本冲突/保存失败时无半更新。

### 验收标准

真实服务能识别正常样本；用户确认前不生效；去重不漏同行费用；导入后红线与手动输入一致。仅 active 票生成当前约束，T30 中指定原票状态、同行票、费用和红线结果正确；资料不足或多人班次冲突时仍保留事实并明确待处理，失效路线/红线不显示为可执行。

### 常见失败情况

把深圳站认成深圳北、缺到达时间时胡编、识别成功即标全票官方核验、原图泄漏；把退票截图当有效票、已退票仍产生红线、替换单张时改坏同行票、旧费用自动清零或新旧票只更新一半。

### Definition of Done

通用 DoD、真实识别路径及 T30 含红线的状态/费用/失败回归通过；仅手动录入或模拟识别不能作为本阶段通过。

### 本阶段不做什么

不做机票截图专项识别、自动购票/退票/改签、证件提取或永久票据相册，不扩展多人分路架构；只记录用户已办成并明确确认的票据变化事实。

## 5. 按这个顺序完成

1. 为 PNG/JPEG/WebP 提供大小/类型校验和发送前裁剪，记录临时文件清理方式。
2. 接通真实视觉模型或 OCR，识别成可修改草稿，缺字段和不确定项明确。
3. 确认日期、站点、车次、时刻与当前有效状态后才提交；退票/替换必须指定原票并确认已办成的事实，复用手工票面短事务，同步真实票据/费用事实、新计划及约束/路线/时间，旧红线失效重算；外部查询失败也保存事实与待补/冲突状态。事实更新继承当前 PlanVersion 的 requestSnapshot/R，需求已改未确认时旧计划继续待更新。
4. 用原图指纹和业务线索提示疑似重复，允许同票、同行票和替换票选择；保留旧票与已支付费用，只改变指定原票，退款另行确认，冲突/资料待补状态如实保留。
5. 验证真实识别、跨日、模糊、旋转、缺金额、取消和清理，并执行 T30 的有效票退票、指定替换、同行仅替换一张及失败原子性回归，加入红线断言；不收集证件用于去重。
6. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
7. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

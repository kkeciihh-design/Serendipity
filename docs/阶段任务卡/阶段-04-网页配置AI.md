## 4. 本阶段详细规格

### 目标

用户能够不改代码地连接和更换 AI 服务。

### 用户能看到什么

密码保护的个人设置页，保存服务信息并看到真实连接结果。

### 功能要求

首次密码设置；Provider、Base URL、Key、模型、测试连接、保存；高级选项提供基础/系统 Prompt 编辑和恢复默认。失败保留旧配置。

### 页面

个人设置与密码验证。

### 交互

用户在页面输入自己的配置；点击测试后保存；AI 负责诊断错误与验证。密钥不通过聊天索取。

### 数据

密码哈希、加密配置、Prompt 内容/版本、连接状态摘要；不保存聊天式测试全文。

### 技术实现

服务端适配器、会话保护、受控网络请求和脱敏记录；远程模式复用单一密码全站保护的配置边界。

### 测试

真实文本连接；错误 Key、模型不存在、超时、无响应、未登录调用设置接口；确认浏览器读取不到秘密；Prompt 保存和恢复。

### 验收标准

实际配置可用于真实请求；更换服务无需编辑文件；敏感写入受保护。

### 常见失败情况

前端暴露 Key、测试成功但未保存、保存错误地址破坏原设置、仅用模拟响应冒充连接。

### Definition of Done

通用 DoD 及真实文本连接通过；缺真实服务条件时不能宣布完成。

### 本阶段不做什么

不做完整后台、多管理员、用户系统或预接地图/搜索。

## 5. 按这个顺序完成

1. 在现有应用中实现首次个人密码与设置访问保护，不建立多账号体系。
2. 实现 Provider、Base URL、Key、模型、测试连接和明确保存；失败保留旧配置。
3. 把密钥留在服务端；实现基础/系统 Prompt 编辑和恢复默认。
4. 用实际可用服务验证文本路径，再测试鉴权、模型名、超时及未登录访问；不索取聊天明文 Key。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

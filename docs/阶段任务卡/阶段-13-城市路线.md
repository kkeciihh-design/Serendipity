## 4. 本阶段详细规格

### 目标

告诉用户相邻地点之间怎么走；真实道路数据在地图显示方向，人工公交参考以文字步骤展示。

### 用户能看到什么

步行、驾车道路路线与方向；公交/地铁外部查询入口及人工记录的线路、上下车、换乘、预计总耗时和每人票价。显示查阅来源、查阅时间、适用出行日期/出发时刻以及“人工参考/待确认”；未知距离、耗时或费用保持未知。

### 功能要求

逐段查询真实步行/驾车路线并显示方向。公交提供无需 Key 的高德官方 URI 入口，带起终点且正确处理坐标系；提示用户在外部地图核对完整日期、出发时刻与运营情况。用户可手动保存可用参考路线或无路线/停运记录，记录多行步骤、包含步行/候车/换乘的总耗时、每人票价（可未知）、来源及查阅时间。人工确认只确认录入依据，不变成服务已核验；无未来自动查询能力，不能把一次耗时平移到其他时刻。

### 页面

地图、时间轴交通行、路线详情。

### 交互

点某段看步骤；切换方式或修改出发时刻后，明确旧记录不适用于新选择。公交重新查阅并确认后保存新版本，更新预计到达、预算和下一项冲突提示。修改相关日程或地点使原结果失效，不继续拿旧到达时刻作新结果；保留历史版本。未保存的表单不会改变已保存计划。

### 数据

RouteLeg、可用时的真实路径折线、步骤、包含的耗时、完整日期/适用出发时刻、费用和来源；人工参考另存原录入、查阅时间、可用性与失效标记。人工公交无折线和自动未来班次能力；未知数据不使用 0 米或 1 秒冒充。旧数据兼容读取。

### 技术实现

地图路线适配、路线缓存、统一时间/费用更新；缓存必须包含完整出行日期及适用出发时刻/有效窗口，并区分地点、交通方式，不能只按同一天复用。需要按新时刻重查时，最多 3 轮候选时刻复核（含首次）；不收敛或缺少未来能力时保持估算或待确认，不宣称精确可执行。检查是否已包含候车换乘，避免重复计时计费。

### 测试

真实步行/驾车查询与真实外部地图入口；人工录入/修改/刷新/重启持久化、历史只读、版本冲突、同日改时刻失效、无路线/凌晨停运记录、未知费用、地图超时、日程冲突和手机布局。T28 使用明确标注的演示班表验证等待时间与缓存隔离，不冒充现实班次；保留 3 轮上限及未来能力缺失的降级检查，不执行阶段 15 红线断言。

### 验收标准

步行/驾车折线和箭头来自可用数据；人工公交不绘制伪路线。文字与所记录适用时刻一致，改变时刻不能错误复用结果。人工保存不进入自动路线共享缓存，永远不宣称自动未来班次已验证。无路线、失效和未知字段明确显示，已失效的费用估计与已支付事实分开处理。

### 常见失败情况

将直线距离当步行、把驾车时长等同叫车全过程、用白天公交套凌晨、同日改时刻仍沿用旧候车耗时、复核无界重试、重复算交通费用。

### Definition of Done

通用 DoD、真实步行/驾车与外部地图入口、人工公交完整记录流程通过；T07/T10 和 T28 的本阶段适用部分、时刻隔离及有界降级检查通过。自动公交 API 与自动未来班次能力不在调整后本阶段的交付范围，不以人工/模拟结果冒充通过；不把后续红线作为本阶段已完成能力。

### 本阶段不做什么

不做车次余票、实时导航、自动叫车或跨城门到门整合；不提前实现阶段 15 的红线倒推、界面或验收。

## 5. 按这个顺序完成

1. 保留真实步行/驾车查询；对相邻地点提供外部公交查询入口与人工参考录入，记录完整日期、适用时刻、来源及查阅时间。
2. 建立包含日期与适用时刻/有效窗口的缓存，显示路径、方向、换乘、上下车、距离、预计耗时和费用依据。
3. 方式或时刻切换后选择适用路线再更新当前已有时间/费用；需要按新时刻重查时最多 3 轮候选时刻复核（含首次），不能收敛或缺少未来能力就标估算/待确认；候车与总耗时不重复。
4. 验证 T28 的路线/缓存部分、夜间无运营、无路线、费用未知和超时，不提前创建阶段 15 红线功能。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

## 4. 本阶段详细规格

### 目标

提前提示这趟旅行真正需要注意的变化和限制。

### 用户能看到什么

与具体活动相关的天气、预约、闭馆、排队、入住、寄存和特殊交通提醒。

### 功能要求

接通可用天气能力并显示日期/更新时间；提醒附触发原因、对象、来源和建议；没有相关条件不展示大段模板。

### 页面

总览关键提醒、时间轴相关提示、清单关联项；设置增加必要天气配置。

### 交互

展开依据、刷新资料、标记已知事项；可进入既有编辑入口调整安排。

### 数据

Advisory、天气预报、适用日期、到期状态、关联事件/清单项。

### 技术实现

少量条件规则结合 AI 简短解释，复用来源体系；超出预报期限如实标无有效预报。

### 测试

真实天气查询；雨天户外、闭馆日、未预约、提前入住、行李寄存未知、天气过期/未来无数据、无关提醒去除。

### 验收标准

提醒能说明与哪项行程有关；已知关闭不能正常推荐；数据失效时不继续声称实时。

### 常见失败情况

把历史气候当实时天气、每天都输出相同长模板、给未去景点提醒预约。

### Definition of Done

通用 DoD 和真实天气能力通过，正常/过期/无数据状态均验证。

### 本阶段不做什么

不自动全程重排，不做后台推送或灾害预报系统。

## 5. 按这个顺序完成

1. 优先复用已选地图天气能力，必要配置加入同一设置页并真实验证。
2. 将天气、预约、闭馆、入住、寄存和交通提醒关联具体事件、日期与原因。
3. 实现资料刷新、时效显示与清单关联，无有效预报范围时显示未知。
4. 检查雨天、闭馆、提前入住、未预约和无关提醒去除，不自动整趟重排。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

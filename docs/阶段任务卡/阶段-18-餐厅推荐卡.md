## 4. 本阶段详细规格

### 目标

让用户选到适合人数、预算和路线的用餐地点。

### 用户能看到什么

餐厅图片、菜品、人均、营业资料、推荐理由和吃完后怎么去下一站。

### 功能要求

实现第 17.3 章餐厅字段；排队仅在有可靠数据时提示；考虑一个人/多人、用餐窗口和合理路线，未知信息明确。

### 页面

时间轴用餐摘要、餐厅详情与候选区。

### 交互

查看菜品、来源和路线；选择候选；人均和人数变化后预算更新。

### 数据

餐厅事实、图片、菜品、人均区间、人数适配、来源及关联费用。

### 技术实现

复用推荐和图片组件；费用按餐次/人数计算，不把每人价格直接当多人总价。

### 测试

正常图片卡、单人与多人、超出营业时段、排队未知、餐厅搬迁/无结果、替换对下一站的影响。

### 验收标准

卡片信息齐全且可解释；没有数据时不编排队时长；餐厅与地图、预算和时间一致。

### 常见失败情况

只推荐热门大桌餐、不看用餐时间、照片属于其他门店、单价和总价混淆。

### Definition of Done

通用 DoD 通过，正常用餐与关键异常在实际页面验证。

### 本阶段不做什么

不做外卖、排队取号、订餐或实时桌位系统。

## 5. 按这个顺序完成

1. 根据人数、预算、用餐窗口和前后站查询少量餐厅候选。
2. 实现图片、菜品、人均、营业资料、人数适配、理由、下一站关系和来源。
3. 可靠排队资料存在才展示，否则显示未知；不要用热度猜队伍时长。
4. 替换餐厅或更改人数时更新费用和路线，测试营业冲突与缺图。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

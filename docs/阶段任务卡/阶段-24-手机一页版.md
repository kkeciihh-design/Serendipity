## 4. 本阶段详细规格

### 目标

把旅行压缩成手机上随时能读的行动资料。

### 用户能看到什么

每一天的时间、地点、交通、下一步和红线，以及可以保存的独立文件。

### 功能要求

按第 20.2 章生成精简 HTML；核心内容离线可读；有按天跳转、版本/时间和待确认事项；默认隐藏私人起点细节。

### 页面

手机一页预览与下载入口。

### 交互

选择日期/全部日期和隐私选项 → 预览 → 下载；说明已验证的手机打开方式。

### 数据

固定已保存计划及其 requestSnapshot/requestRevision、清单和执行状态的导出快照，导出选项、HTML 文件与版本记录。

### 技术实现

从已有计划直接生成内置样式的静态页面，关键内容不依赖脚本、外链资源或持续服务器连接。

### 测试

T22/T26；断网打开、两天/四天、长地名、跨日红线、隐私隐藏和真实支持的手机环境；T29 的导出部分：需求已修改而旧计划未更新时，文件仍使用旧计划自身日期、人数及预算依据并标明待更新。

### 验收标准

离线仍有全部关键行动信息；没有假实时状态；手机字号、滚动和日期导航可用。

### 常见失败情况

下载后依赖本地服务器、把四天挤一屏、隐藏文字却留下住址坐标、只测桌面。

### Definition of Done

通用 DoD 通过，独立文件实际断网检查，支持环境与限制如实记录。

### 本阶段不做什么

不做 PWA、离线地图、离线 AI 或复杂缓存同步。

## 5. 按这个顺序完成

1. 固定已保存计划及其 requestSnapshot/requestRevision、清单和执行状态快照，生成精简的按日手机行动视图；不从当前待更新需求拼接字段。
2. 提供独立HTML，内置关键样式，离线关键内容不依赖服务器/脚本。
3. 加入版本、生成时间、待确认事项和隐私选择，隐藏住址同时处理坐标/链接/内嵌数据。
4. 实际断网测试，并按真实可验证的浏览器/手机环境记录支持方式；本阶段不显示尚不可用的长图/PDF按钮。

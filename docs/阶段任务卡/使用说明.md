# 阶段任务卡使用说明

本套任务卡交付时，项目只有开发文档，所有开发阶段都尚未开始。网页、地图、AI 连接和导出等产品功能还没有实现。接下来由你按顺序打开新窗口，让 Agent 每次完成一个阶段；本套文档不会自动创建窗口或开始开发。

先打开[任务卡目录](README.md)，从[阶段 00：项目骨架](阶段-00-项目骨架.md)开始。一个窗口只做一个阶段，每个窗口都使用同一个项目文件夹：

`C:/Users/11295/Desktop/Serendipity`

不要为下一阶段另建一个空项目，也不要同时让两个窗口修改这个项目。前一个阶段通过并结束后，再开启下一个窗口。

你只需打开对应任务卡，复制全文粘贴给 Agent；也可以让能访问文件的 Agent 直接读取这张卡。两种方式任选一种，不必每次复制开发总文档，更不用自己运行命令。任务卡会要求 Agent 自动读取相关规则、项目现状和交接记录。

执行开发的 Agent 需要能访问项目文件、运行检查并打开网页。只有文字聊天能力的窗口可以讨论方案，但不能把讨论当成已经开发或验收成功。

下面这段可直接复制到你新开的第一个窗口：

> 请以 C:/Users/11295/Desktop/Serendipity 为工作目录，完整读取 C:/Users/11295/Desktop/Serendipity/docs/阶段任务卡/阶段-00-项目骨架.md，只执行阶段 0。请自动读取任务卡要求的资料，检查实际项目状态，由你完成环境准备、开发、启动、测试、修复和验收。不要提前实现下一阶段，不要让我运行命令、查看控制台或检查代码。完成后按任务卡写好开发进度、阶段验收和阶段交接记录，给我实际网页入口与明确结论，然后结束本阶段。

每个阶段都由 Agent 自己判断是否达标，并留下三类文件：

- `docs/开发进度.md`：现在做到哪里、哪些已通过、当前还卡在哪里。
- `docs/阶段验收/阶段-NN.md`：实际运行了哪些检查、结果和证据，以及明确验收结论。
- `docs/阶段交接/阶段-NN.md`：本阶段改了什么、怎样继续运行、重要限制和下一阶段需要知道的事实。

这里的 NN 是两位阶段编号，例如阶段 0 写“阶段-00.md”，阶段 1 写“阶段-01.md”。这些记录由 Agent 创建和更新，不需要你填写。没有实际执行的检查必须写“未验证”，不能编造通过证据。

下一个 Agent 会自动读取开发进度、前一阶段的验收与交接文件，再检查真实项目。你不必转述上一窗口的技术细节，也不必判断数据库或接口是否正常。新窗口接着同一个项目工作，不是重新从头写一遍。

只有结论为“通过”，才进入下一阶段。如果是“不通过”或“外部条件待验收”，就留在当前阶段修复或补齐条件；换窗口继续时仍使用当前阶段的卡，让 Agent 读取已有记录并接着处理。不能跳到下一张卡掩盖失败，也不能让你点击确认来代替技术验收。

遇到需要你自己的密码、服务密钥或付费决定时，Agent 应说明最少需要什么，并通过产品设置引导你完成。连接诊断、测试和修复仍由 Agent 负责，你不用学会调试。

未来阶段的任务卡是蓝图。开发中实际文件、运行方式或依赖发生变化后，Agent 应更新进度与交接材料，按已经验证的事实适配当前任务；必要调整要说明原因。它不能照抄过期安排，也不能借此删掉第一版必需功能、擅自扩展范围或提前开发后续阶段。

换电脑或更换开发工具时，要让新 Agent 能访问整个项目，以及总文档、执行规则、任务卡和最新的进度、验收、交接材料。只有上一段聊天或一张任务卡不够。如果旅行数据放在项目文件夹之外，也让 Agent 按备份方案迁移并检查恢复；服务密钥通过设置重新填写。

你每次只需要描述想做的阶段、观察网页、反馈哪里不好用。安装、代码、运行、检查、修复和技术交接，都交给 Agent 完成。

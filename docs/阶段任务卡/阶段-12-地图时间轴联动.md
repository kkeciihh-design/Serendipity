## 4. 本阶段详细规格

### 目标

让用户能在地图和时间轴之间找到同一项安排。

### 用户能看到什么

①②③等编号与日程一致，点击任一侧时另一侧定位到对应事件。

### 功能要求

按当天到访顺序编号；双向选中/定位；同酒店重复到访有可选择时段；切天、编辑、移除后保持一致。

### 页面

桌面时间轴加地图、手机地图摘要与行程页。

### 交互

时间轴点地点 → 地图聚焦；地图点编号 → 滚到对应日程；手机可从摘要跳转。

### 数据

复用事件/地点 ID，仅从顺序计算展示编号；不另存一套地图行程。

### 技术实现

共享日期与选中事件状态；重叠点合并展示但不合并到访事件。

### 测试

T06；一天两次酒店、跨天同地、改顺序、删除选中项、两侧快速切换、键盘导航。

### 验收标准

两侧定位到正确日期和事件，编号不漂移，没有双向触发造成的无限滚动。

### 常见失败情况

用地点 ID 代替事件 ID、数组顺序变化后点错项、切天只刷新地图。

### Definition of Done

通用 DoD 通过，实际浏览器双向联动和多次到访用例通过。

### 本阶段不做什么

不生成道路路线，不增加地图拖拽改行程。

## 5. 按这个顺序完成

1. 按每天到访顺序生成编号，使用事件身份而非地点身份选择日程。
2. 实现时间轴定位地图、地图定位正确日期和事件。
3. 处理同一酒店多次到访的重叠点和时段选择。
4. 验证改顺序、删除选中项、切天、窄屏摘要跳转和连续点击。
5. 运行下面的验收项，发现失败自行修复并复测；保存实际结果，不复制预期冒充已通过。
6. 更新开发进度、本阶段验收和交接文件，向用户提供入口与结论，然后停止。

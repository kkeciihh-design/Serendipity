## 数据、接口和状态约定

- 本阶段没有新增数据库表或迁移；事件继续存放在 `PlanVersion.events` JSON 中。
- `PlanEvent` 新增兼容字段：`endDate`、`order`、`status`、`locked`。旧计划缺省时按 `endDate=date`、`status="suggested"`、`locked=false` 读取；新保存版本会补齐这些字段。
- `date` 是开始日期，`dayNumber` 归属开始日；跨午夜事件用 `endDate` 为次日和 `endTime` 表达。结束时刻等于开始时刻按零时长拒绝；结束时刻早于开始时刻且未显式给 `endDate` 时按次日解释。
- 普通编辑只允许当前 `PlanVersion`，历史版本只读。保存时创建 V+1，继承原 `requestRevision`、`requestSnapshot`、`pendingItems` 和 `requirementUpToDate`，并用该计划自己的快照重新执行当前已有校验。
- 最新需求修改、未确认或待应用时，普通编辑仍可保存真实事实；新版本继续标待更新，不改用最新 `TripRequest`。
- 已锁定事件不能同时修改时间、状态、备注或删除；只能先单独取消锁定生成新版本，再进行其他修改。去程/返程固定交通不能删除。
- 事件 ID 在编辑、重排和移除时保持稳定；`order` 只按时间顺序重算，不作为身份。
- 时间轴衔接覆盖同日事件和当天最后一项到次日第一项，只计算间隔并显示“路线未核验”，不创建新的交通耗时、费用或可达性结论。

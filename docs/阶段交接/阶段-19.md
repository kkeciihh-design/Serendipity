## 数据口径

无新增依赖、数据库表或迁移，仍为10个既有迁移。使用 `PlanVersion.events/costs/places/routeLegs` JSON 的可选字段；旧版本不批量回写。

`PlanEvent.accommodationSelection?` 包含：

- `stayId`：连续入住的稳定分组（基于首个住宿事件ID）；每天仍保留独立事件ID。
- `areaId / areaName`：偏好方向及名称。`kind=area`表示区域参考；`kind=hotel`仅表示用户核对了具体酒店地点，不是已预订。
- `checkIn / checkOut / nightCount / roomCount`：完整日期、离店减入住的夜数（1–3晚），房数1–100。日期在旧计划自身需求快照内，选中的每晚必须恰有一个住宿事件；不能只覆盖已有入住分组的一部分。
- `morningDepartureTime`：本次连续入住每天次晨离店时刻；本版使用同一时刻。`checkInFrom / checkOutBy`可为空，`luggageStorage`为unknown/available/unavailable，`conditionNote`保存用户提供的条件说明，`selectedAt`记录核对时间。这些不是官方核验或实时房态。
- `invalidatedAccessOrigins`：被替换住宿曾用作票据人工接驳起点的关系。旧耗时失效，票据原事实不改；用户通过门到门入口更新起点后再核对红线。

`PlanCostItem.roomCount?` 仅适用于住宿的 `per_room_per_night`。每个住宿事件的费用行是**该晚1晚**：单价×该行roomCount×1；两晚分别两行，不再乘整次nightCount或整趟人数。整次nightCount供分组展示。旧行无roomCount继续按快照ceil(人数/2)；无nightCount继续保留旧预算口径。预算入口可确认金额与支付，关联入住的单行不能改成多晚；转回按房/晚时使用该入住明确房数。

区域参考价格是**已有住宿预算的每房每晚分摊**，不是地区市场价，未知保持null。实际酒店价格和房态分别显示；手填金额为估算，付款仍在预算入口处理。已确认/已支付的住宿费用、锁定/确认的住宿不被推荐覆盖，已有支付的路线费用保留。

旧按晚费用如果没有nightCount，按其原全程夜数把行总额换算回每房每晚，不能把全程总额误标为单晚参考价；该转换只用于比较，不回写旧费用。

所有保存继承旧计划 `requestSnapshot / requestRevision`，新需求尚待应用时继续标待更新。AI输出不能写accommodationSelection。新住宿地点不能绕过住宿入口从通用地图编辑，避免分组与预算脱节。

## API与一致性

基础路径 `/api/trips/:id/plans/:version/accommodations`：

- `GET ?eventId=...` 返回 `{recommendations}`，历史可读，含区域、比较、默认值和保护说明。
- `POST {action:'preview',eventId,stay}` 返回 `{preview}`。stay包含kind、areaId、hotelToken（已有确认酒店可null保留）、routeMode、完整日期/房数/金额/条件和acknowledged=true。预览不写库。
- `POST {action:'apply',eventId,previewToken}` 返回 `{plan}`及其来源。客户端不能在apply中重写地点、价格或日期。
- 酒店搜索复用既有 `/places` POST。只接受本旅行/版本/事件的有效签名token、同城且明确hotel/hostel等类型的具体POI。地图误返外地、区域类或过期候选被拒绝。

服务器缓存最多100项、10分钟，重启失效；涉及住宿的已知路线超过15分钟需重新预览。最终短事务重读当前版本、检查所有相关事件与保护费用，原子写入V+1和当前指针；事务内不联网。并发仅一项成功，异常全部回滚，重复apply拒绝。网页读取/搜索/保存30秒超时，预览100秒；查询可取消，保存未返回提示刷新核对。

路线沿用OSRM/高德适配和人工公交能力边界。一天内的住宿到次晨路线使用 `routeDayEvents` 投影；地图用“宿”标识，点击回到原晚事件。区域没有具体酒店时不查询精确路线；确认酒店查询前后相邻已定位地点。未知、离线或待重查人工路线清除旧路径/耗时，保留必要的未知车费，不冒充免费；已知迟到、明确预算/步行上限及新增返程红线冲突阻止应用。

当前规则不把“酒店可寄存”当成提前入住；明确不可寄存且早到会阻止应用，未知则提示核对。活动过远按参考直线和实际查询分别表达。酒店距偏好参考点较远时提示以实际酒店路线为准。参考资料不足时明确无法确认全部约束成立。

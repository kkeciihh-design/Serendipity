## 本机识别与隐私

采用 Tesseract.js 7.0.0（Apache-2.0）、`@tesseract.js-data/chi_sim` 1.0.0（包声明 MIT）和 sharp 0.35.5。锁文件已更新，无 Next / React / Prisma 升级；实际依赖审计无已知漏洞。模型随 npm 安装，运行时没有模型下载、外部视觉请求、API Key 或计费依赖。它是实际 CPU OCR，不是测试固定返回值。

原图仅在浏览器 ImageBitmap 中用于裁剪；原图 SHA-256 在浏览器生成，服务器只接收裁剪重编码的 PNG。输入为静态 PNG / JPEG / WebP，单张≤10MB、像素≤2000万；服务器再次检查文件签名、解码和页数，去 EXIF 并限制识别边长 2400。JSON Base64 有体积膨胀，Next `experimental.proxyClientMaxBodySize` 设 15MB，接口自身仍严格限制图片 10MB。

没有临时票图目录、公开图片 URL、原图数据库列或磁盘清理任务。服务端图片和 OCR 原文仅在请求内存及子进程中存在；成功、失败、取消、60 秒超时均结束子进程，模型未加载成功也能强制终止。每个应用实例同时只识别一张，忙时返回 429。浏览器关闭面板、确认成功、离开组件或 30 分钟到期释放图像；确认前取消不发票据写请求。未确认草稿默认只在页面内存，用户主动“保存草稿”时才保存结构化字段，草稿不产生约束和费用。

不提取姓名、证件号或订单号。保存字段仅有旅行必要票面、匿名人数 / 座位和来源；图片、原始 OCR 文本不进入日志、Git、备份或导出数据。阶段 24 以后新增分享导出时，必须默认隐藏座位，不能直接把票据 JSON 全量导出。

## 数据与确认协议

`Ticket.id` 仍是稳定票据身份（任务卡称 ticketId）。四态 `draft / active / cancelled / replaced` 不变；`confirmedAt` 只是历史确认时间，仅 `active` 且已确认参与当前约束。`seat?: string | null` 可选，旧票缺值正常读取；已确认非空座位同关键票面一样不能直接改写，变更走指定替换。

`Ticket.importSource?` 保存 `{ engine: 'tesseract-local', imageFingerprint, cropFingerprint, recognizedAt, documentKind }`。不保存模型自报概率或整张票官方核验结论。`documentKind` 是识别提示，用户仍须确认真实当前状态。

`POST /api/ticket-import` 接收 `{ image: 'data:image/...;base64,...' }`，返回 `{ draft }`，包含 `segments[].fields / notices`、文档种类、裁剪指纹及识别时间；完全不修改当前计划。用户先选择当前去返程，再选择新票 / 同一张 / 同行 / 指定替换 / 指定退票，核对原票及票面。

提交仍是 `POST /api/trips/:id/plans/:version/tickets`：`activate / create_draft / replace` 可带 `importSource` 和 `importResolution=new|companion|replacement`。发现相同图片或同日期、车次、站点时，普通新票提交会被服务端拒绝，必须明确同行或替换；“同一张票”直接跳过，不写新版本或费用。不同座位只作为同行提示，不自动合并。退票资料禁止走新票生效，改签资料必须指定替换。退票使用既有 `cancel {ticketId, acknowledged:true}`，该动作只改变指定原票，原有识别来源保留。

事务复用阶段 14：核对当前计划版本，保存票面 / 状态 / 独立费用 / 新计划 / 事件与旧路线失效。替换同时保存新票 active、旧票 replaced 和 replacedByTicketId；退票只将指定票 cancelled。仍有效同行票维持共享事件。不同班次或资料不足仍保存事实，显示冲突 / 待补；没有扩展多人分路。

事实提交继承当前 PlanVersion 的 `requestSnapshot / requestRevision`，不能采用尚未确认的新需求；计划继续待更新。没有事务内 OCR 或外部路线请求。路线离线不阻止已确认事实，旧派生路线清空 / 待重算；红线按当前版本和 active 票重新生成，历史不冒充可执行。版本冲突或最后数据库更新失败时整个事务回滚。

每票有独立费用身份，未知金额不是零。同行同班次保留独立票数及费用；已支付旧费用不因退改票清零，实际退款在阶段 09 预算入口另行确认。接驳共享规则沿用阶段 14。

## 限制与下一阶段

OCR 不保证任意铁路客户端皮肤、复杂混排或严重模糊图片都准确。无标记的新旧多票混排会清空不可靠字段并要求分别裁剪；有明确“第几段 / 行程数字”边界时可以逐段选择。旋转票需在发送前旋转到正向，不宣称自动方向检测。缺年份、到达日期或金额不自动补造，次日 / 同日推断明确提示，所有关键字段由用户核对。

本阶段没有云端视觉模型、多服务配置、机票 OCR、自动购退改、永久票据相册、证件识别、多人分路或远程部署。沿用阶段 15 的红线精度和人工接驳限制。

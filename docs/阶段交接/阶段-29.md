## 持久配置、控制协议与数据

正式根目录仍为 `C:/Users/11295/AppData/Local/Serendipity`，库为 `data/serendipity.db`。无新迁移、字段或业务版本规则；保留阶段28的dataGeneration/恢复屏障、R/V与旧页面失效协议。

`runtime/launcher.json` 保存版本1、projectRoot、dataDirectory、nodePath、buildDirectory、preferredPort及databaseRequired。入口使用持久绝对路径，不读取临时测试实例环境；启动清除继承的SERENDIPITY_*、DATABASE_URL、NODE_OPTIONS、NEXT_MANUAL_SIG_HANDLE、PORT后显式设置本机生产环境。Node安装或项目移动时维护者修复此配置/重新安装入口。

`runtime/service.json` 是运行期状态，含实例ID、PID、实际业务/控制端口、随机256位控制令牌、数据/应用/构建路径、启动时间。**含控制凭据，不提交Git、不复制到公开报告**。浏览器/API仅接收无令牌的安全状态。`runtime/initialized.json` 标记已成功初始化，数据库丢失时拒绝自动建空库；生产安装时已有库还通过databaseRequired保护。

`runtime/service.log` 保存本机维护日志，启动时超过2MiB滚存一份`.previous`。`last-error.json` 保存本次失败的中文摘要和PID，无密钥。日志不在public目录，不纳入普通旅行备份。状态目录和数据库都不在Git中。

Windows具名管道按真实规范数据路径的SHA-256标识，分别用于短操作串行和服务生命周期单实例锁，随进程退出释放，不依赖手工删锁文件。PID探测仅用于拒绝不明状态；控制器不凭PID强杀。私有HTTP控制端口只绑定127.0.0.1，校验Host、无Origin和随机Authorization令牌；status返回自身身份，stop返回后触发Next的SIGTERM处理完成请求与关闭。网页可访问还需身份/PID/数据库路径与启动配置匹配，才返回ready。

启动顺序：文件及读写预检→选择端口→建立私有控制状态→真实`ensure-database.mjs`（沿用备份/迁移/恢复接续）→Next startServer→GET `/api/runtime`核对→打开网页。端口抢占竞态会启动失败，不打开未知网页。停止超过30秒时提示仍在结束操作，稍后查状态；不声称已停止。

不要同时通过手动`npm run start`和桌面启动器运行同一数据目录。具名管道保证本套启动器之间不重复，不会自动接管历史手工启动的实例；本轮已核对旧正式3003父子关系并受控停止，然后由新入口启动。

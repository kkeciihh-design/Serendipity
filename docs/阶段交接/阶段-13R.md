## 必须保留的实现约定

1. 金额以 PlanVersion.costs 和自身 requestSnapshot 计算。PlanEvent.costDraftCents 只保留原生成数据，不能重新当作当前金额用于时间轴或预算警告。
2. PlanCostItem.nightCount 是可选字段，新每日住宿为 1。旧 nightly 费用缺该字段时保留全程晚数口径，用户在费用编辑页确认实际晚数后创建新版本。不要批量重算旧已付历史。
3. `hasProtectedCostFact` 统一识别用户确认、付款及退款待处理事实。删除事件只移除纯预测；付款不等于退款。序列化过滤历史遗留的纯预测已移除项，不修改数据库历史 JSON。
4. 路线整段票价按 `routeCostPricingUnit` 计一次。可选 `transportEventIds` 把一条路线与中间交通/换乘关联；旧字段缺失时在事件编辑中用 previousEvents 推导。保护事实优先，部分付款剩余项未知；交通移出原区间仍保留未知项，重新查原路线不能吞掉它。
5. 路线失效依据相关地点/时间/顺序/类型，包含中间交通删除/移动；备注、锁定、确认及不影响到达约束的目的地结束时刻不触发无意义失效。
6. 需求存储读取使用兼容 Schema，新 AI 输出、保存及确认走严格日历校验。相对时间按北京时间；无法理解的天数或结束日期需追问。
7. 来源限制解析有边界：无法解释的闭馆/入场限制应待确认，不按默认开放时段升级已核验。门票证据选择唯一非路线门票项，不能误选附加公交费用。
8. 时间轴/预算草稿按旅行和稳定 ID 缓存；服务端版本更新走三方字段合并。冲突显示新版值并保留本地输入，恢复原值采用最新版本。锁定项目要先单独解除锁定，待改内容保留到下一次保存。
9. 指定版本 URL 保存成功后切到当前版本地址；读取历史保持只读。不要将仅 `router.refresh()` 恢复成唯一保存后动作。
10. 现行测试入口统一为 `npm test` 和 `npm run test:e2e`；旧 verify/capture 03–10 已安全停用，不恢复那些绕过隔离校验的历史脚本。

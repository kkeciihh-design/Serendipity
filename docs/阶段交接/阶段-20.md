## 独立存储与身份

`ChecklistState`以`tripId`为主键，旅行删除时级联删除；字段为`revision`、`planVersion`、`items` JSON、`updatedAt`。勾选不创建新的`PlanVersion`，不更新票据、费用、预约事实或旅行状态。时间戳保存ISO UTC，页面明确以北京时间显示；事项日期使用计划自身需求快照。

每项保存`id/group/title/note/date`、`eventId/eventIds/ticketIds`、`source/sourceLabel/sourceKey/signature/officialUrl`、`custom/completed/completedAt/deleted/orphaned/changeNote`。自建ID为`custom:UUID`，生成事项分别用交通事件、入住组/住宿事件、预约事件的稳定ID；未匹配活动的预约说明按规范化标题与日期建立稳定身份，不信任模型重复的说明ID。基础物品仅两项：有效证件、手机和充电器。没有为每个普通活动添加无关预约模板。

连续入住的多个住宿事件合并为一个住宿准备事项，保留全部相关事件链接；未建立连续入住组的每晚住宿分别保留。交通事项关联该交通事件全部active票据；草稿、已退票、已替换票不参与。票面核对不会自动完成清单。铁路提供12306官方入口；预约复用已有目录中的官方链接，保留原获取日期；无法确认的酒店/航空/场馆入口不编造链接。已有EvidenceFact预约字段参与是否需要预约的判断，失效或未核验资料仍要求核对。

## 合并与一致性

1. 优先按稳定ID匹配。完整生成返回新的模型事件ID时，仅对唯一、语义对应的到访匹配旧身份；同类型、日期、地点名称、开始时刻构成辅助关系，签名再核对实质内容。
2. 仍相关且内容未变的完成状态和时间保留；日期、地点、同行人数、票据或预约备注/来源要求等实质变化后，生成事项回到未完成并显示变化说明。基础物品不因计划日期变化而清空已准备状态。
3. 新事项默认未完成。已移除的生成事项标`orphaned`、留存原记录、不计入当前进度；重新出现须重新核对。移出清单使用`deleted`墓碑，重复生成不会自动恢复，可手动恢复。
4. 自建事项的标题、备注、日期和勾选保留。原关联活动消失或日期变化时提示核对，不删除自建事项；关联日期须与选中的活动一致。
5. 七个既有计划写入入口（生成、事件、费用、地点、路线、景点/餐厅/住宿共用推荐、票据）在同一短事务中同步清单。计划、当前指针与清单任一失败全部回滚，事务内没有外部服务请求。
6. 生成开始捕获`expectedChecklistRevision`；提交重新读取最新修订并合并生成期间的新勾选，不把起始状态写回。正常并发进度增加允许合并，修订倒退拒绝；Plan R/V仍按原协议检查。阶段28的代际机制尚未引入。

旧计划没有清单行时，GET只返回按当前计划整理的视图、修订0，不写数据库；首次保存或下一次计划写入才建立清单。来源资料可独立刷新，因此每次读取还返回`basis`（规范化内容SHA-256）。写入同时校验计划V、清单修订和所见来源内容指纹，避免旧页面确认已变化的预约资料。来源内容指纹不是认证凭证，不替代权限检查。

## API与失败恢复

- `GET /api/trips/:id/checklist?planVersion=N` → `{checklist:{tripId,planVersion,revision,updatedAt,basis,items}}`，只允许当前计划，不缓存。
- `POST /api/trips/:id/checklist` → `{expectedPlanVersion,expectedRevision,expectedBasis,change}`。change是`sync`、`complete {id,completed}`、`add {id:UUID,fields}`、`edit {id,fields}`、`delete {id}`或`restore {id}`。
- fields仅有`title/group/note/date/eventId`，不能附带票据状态、完成时间或官方链接。自建名称160字、备注500字；最多200个未移出的自建事项，存储总记录最多2000项。
- 400格式或关联无效；401未授权；403来源不可信；404计划不存在；409版本/内容冲突或旧计划；503读写不可用。
- 前端等待服务器成功才改变勾选，保存期间同步锁阻止双击；显式设置completed而不是服务端反转。失败保留原勾选及表单，“重试刚才的保存”沿用原页面版本；冲突须重新读取后核对再提交。新请求30秒超时；超时/响应丢失不宣称未写入，提示重新读取核对。卸载后的迟到结果不更新页面。
- 纯清单重复更新不改变内容时不增加修订；计划每次写入都会记录所用计划版本并递增清单修订。

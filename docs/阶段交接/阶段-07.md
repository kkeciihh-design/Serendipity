## 数据、接口和状态约定

- 总览只读取所展示 `PlanVersion` 自身的 `requestSnapshot`、`events`、`pendingItems` 和 `validationResults`，不拼接最新 `TripRequest`。
- `requestState.requestRevision` 只用于判断当前计划是否待更新和是否允许生成；`requestState.hasUnsavedEdits` 单独提示未保存编辑，不直接写入计划状态。
- `planRequiresUpdate` 同时检查持久化标记 `requirementUpToDate` 和计划绑定的 `requestRevision` 与最新需求修订是否一致。
- `planStatusLabel` 区分“尚无计划”“当前计划待更新”“需求依据当前有效”“历史版本”“历史版本待更新”。
- `buildPlanOverviewDays` 按事件 `dayNumber` 分组、按开始时间排序，并从同一计划快照生成每日主题。
- 当前版本切换后，已选日期重置为第 1 天；历史版本通过 `?planVersion=N` 打开。
- 生成新版本仍复用阶段06 API 和双版本提交保护；本阶段没有新增 AI 调用路径。

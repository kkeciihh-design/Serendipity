## 本阶段新增或改变的数据/接口约定

- `TripRequest` 与 `Trip` 一对一，包含原话、`requestRevision`、提取结果、字段来源、默认假设、待确认问题、`confirmedRequest`、`confirmedRevision`、`confirmedAt`。
- 新建 Trip 时 TripRequest 从修订 1 开始；既有草稿迁移补齐为修订 1 且未确认。
- 需求快照字段：目的地、出发/返回日期、人数、预算分、预算口径、节奏、兴趣、住宿、限制和字段来源；日期为 `YYYY-MM-DD`，金额为人民币分。
- `PATCH /api/trips/[id]/request`：携带 `expectedRequestRevision`；原话或需求快照实际变化时条件更新、修订 +1、清除确认。无实际变化不递增。
- `PATCH /api/trips/[id]`：修改原话必须携带 `expectedRequestRevision`；实际变化时修订 +1、清除提取和确认。标题修改不影响需求修订。
- `POST /api/trips/[id]/request/extract`：携带启动修订；服务端读取当前原话并调用 AI，受控 JSON 经 Zod 与业务校验，最多修复一次；保存时条件核对修订和原话，成功后形成待确认草稿并修订 +1。
- `POST /api/trips/[id]/request/confirm`：只接受当前已保存修订；确认时冻结 `confirmedRequest` 并记录 `confirmedRevision`。确认要求目的地和具体日期，2～4 天，未来日期；可选偏好缺失不阻止确认。
- 页面用同步 ref 读取等待期间的最新未保存编辑；迟到提取结果只更新服务端基线，不覆盖本地输入。
- AI 输出中的 `user_confirmed` 在提取阶段统一转换为 `ai_extracted`；`user_confirmed` 只能由用户编辑产生。
- 阶段06只能使用 `confirmedRequest` 和对应 `confirmedRevision`，不得使用未确认的 `extractedRequest`；本阶段未建立 PlanVersion。

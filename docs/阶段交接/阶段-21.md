## 数据和一致性约定

`AdvisoryState`以`tripId`为主键，旅行删除时级联删除；保存`revision`、`planVersion`、`items` JSON、`weather` JSON和`updatedAt`。`weather`包含`records`与`aiStatus`。不修改不可变PlanVersion，不把已知标记当作预约成功、清单完成或解除关闭限制。

每条提醒包含类别、严重程度、时效、适用日期、标题、对象、原因、建议、可选AI解释、`eventId/eventIds/checklistItemId`、来源URL/名称/时间窗口、SHA256签名和已知时间。签名绑定活动日期/时段/地点及规则输出；单纯获取时间改变不撤销已知，实质内容改变重置为未读。AI说明单独标为非事实核验，不参与严重程度或硬约束判断。

GET在短事务中核对当前计划指针，同时读取来源和派生清单，按当前计划重新投影提醒。没有存储行时返回修订0且不写数据库。计划变化无需在七个计划写入入口额外写提醒：旧存储只是已知及天气缓存，读取时按新计划重投影；旧计划请求409，移除活动的提醒不再展示。仍相关且签名不变的已知事项保留；历史计划不展示当前状态为历史快照。

POST先捕获Plan V、提醒修订及来源/清单内容指纹。外部天气及AI请求在事务外完成；最终短事务再核对当前指针、修订、来源及清单指纹，并CAS更新提醒。来源或清单在外部工作期间变化则拒绝旧结果。确认已知还校验该提醒的签名，来源/时效变化不能用旧页面确认。请求取消或保存失败不更改原计划。

天气仅从已有确认地点或匹配的有限景点/餐厅目录取坐标，不把目的地名猜成某个地点。GCJ-02转WGS84后取约1公里单元，同一单元共用预报；单次最多12个位置、4并发，每个最多10秒，其余显示未查询。只有当前活动位置和日期匹配的缓存能使用。缺少坐标、超范围、接口失败、字段缺失、过期分别保留未知或降级状态，不用历史气候补数。

预报最长包含北京时间今天至第15天，共16天；保存UTC ISO时间，页面用北京时间。缓存达到1小时或日期已过即失效，未来获取时间也不能视作有效。客户端每60秒/重新获得焦点/清单或来源保存后重读本机状态，不自动调用外部天气；旧数据无法读取时显示错误，过期降水提醒也不会继续显示为有效。

## API

- `GET /api/trips/:id/advisories?planVersion=N` → `{advisories:{tripId,planVersion,revision,updatedAt,items,weather,missingWeatherEventIds,aiStatus}}`。
- `POST /api/trips/:id/advisories`：`{action:"refresh",expectedPlanVersion,expectedRevision}`，或`{action:"acknowledge",expectedPlanVersion,expectedRevision,advisoryId,signature,acknowledged}`。不接受客户端写入事实、AI说明、来源或办理状态。
- `GET /api/settings/weather`只返回安全状态；`POST /api/settings/weather/test`真实查询北京当日预报并返回短期签名token；`POST /api/settings/weather`以token保存测试状态。
- 提醒POST最多4000字符；前端同步锁防双击、50秒超时和卸载取消。超时/响应丢失提示重读核对，不声称一定未写入。所有提醒响应不缓存。

## 规则与来源

预约派生复用阶段20的真实清单ID及来源规则，仅关联活动未完成项产生提醒；完成清单只表示用户自行确认。闭馆优先使用适用EvidenceFact，精确目录闭馆日与未验证常规闭馆日分开。已知闭馆持续显示“需处理”，原景点推荐排除逻辑继续生效，不改变行程时刻。

入住规则使用首次入住事件和已填酒店条件，早于允许入住或时间未知时提示；涉及提前到店/行李且不可寄存或未知时提示寄存。排队仅匹配具体餐厅/明确排队说明；暂无可靠数据不编造等候分钟。交通仅对无运营、冲突、需重核路线或有效票据的行李说明提醒，停用票据不参与。

雨天只对按活动名称/说明识别出的户外活动触发，降水概率≥50%、总量≥5mm或降水天气代码满足规则；每日预报不保证活动时刻一定下雨。普通来源刷新继续走活动编辑中的既有来源入口，天气刷新不抓取全部官网。来源目录仍保留原获取日期。

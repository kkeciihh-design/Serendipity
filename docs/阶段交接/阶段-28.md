`GET /api/settings/backup`：须个人管理员会话，下载`application/json`，no-store/nosniff。64 MiB上限；文件名固定应用前缀与日期，不用用户输入拼路径。

`POST /api/settings/backup`：须会话、同源及CSRF；preview/restore还须页面`x-data-generation`。

- `{action:"preview",backup:<JSON对象>}`：严格验证后返回incoming/current摘要、当前旅行哈希与备份哈希、10分钟有效的签名`previewToken`。只预览不写旅行/不设置屏障。
- `{action:"restore",backup,previewToken,confirmed:true}`：重新验证文件/令牌/当前代际，在建立屏障的事务内再次比对预览时当前旅行哈希；任何新编辑要求重做预览。不能绕过明确确认直接恢复。
- `{action:"resume"}`：接续未完成的保护/回退；仍活动的恢复不能被此操作清屏障。这个管理入口不要求旧页面先有可写代际，便于屏障状态下处理。
- 普通业务写入缺失/旧代际409 `code:DATA_CHANGED,reloadRequired:true`；屏障423 `code:RESTORE_ACTIVE,reloadRequired:true`。既有R/V/状态冲突仍使用原业务检查，不等同于数据恢复。

## 格式、数据和排除范围

格式：`{format:"serendipity-travel",version:1,createdAt:<ISO>,tables:{...}}`。严格支持版本1，未知字段/版本拒绝。行顺序按稳定id/tripId规范化，日期保留SQLite实际毫秒值（兼容合法ISO），业务JSON列保留原字符串，通过既有Schema复验。

纳入 `Trip, TripRequest, PlanVersion, EvidenceFact, ChecklistState, ExecutionState, AdvisoryState` 的明确列，包含全部计划版本、绑定需求修订/不可变快照、事件/金额/地点/路线/票据必要字段与有效状态、来源与许可资料、清单及执行进度。

## 恢复协议与全部写入入口

1. 文件Schema和预览通过、用户明确确认后，`BEGIN IMMEDIATE`内核对预览哈希/代际，写RestoreOperation与activeRestoreId并提交屏障。
2. 屏障内一致读取7张旅行表，空间预检后写`<实例根>/backups/before-restore-<id>.json`，独占创建、fsync、读回格式及哈希验证；持久标记ready及安全路径/哈希。
3. 短事务中清除旧旅行、按FK次序插入新内容、恢复当前计划指针，检查完整性/引用与旅行内容哈希；**同一事务**写成功记录、随机新代际、清屏障。外部AI/地图/渲染均不在此事务。
4. 屏障后失败，先验证原旅行内容是否仍完整；若不是则用已记录且校验通过的安全副本真正回退。保护后在同一事务换代并解屏障。保护/回退/换代任一步失败，保留屏障。
5. 启动器先处理未完成恢复；活动任务Set和ownerPid防止另一条接续请求抢先清除尚在运行的屏障，其他活进程占用时拒绝。退出中断后SQLite回滚未提交替换，重启校验原状态/必要回退，再换代。普通重启无活动屏障时保持代际。

## 技术恢复、回退和未完成接续

维护者入口：`node scripts/technical-restore.mjs <实例根绝对路径> <备份JSON或DB绝对路径>`先预览；核对目标、影响与摘要后加`--confirm <本次confirmation>`执行。confirmation绑定目标绝对路径、旅行哈希和代际，改变数据后旧确认失效。`.db`只提取白名单旅行表，绝不覆盖当前数据库文件、迁移表、密码、服务设置或实例代际。

回退可选该操作记录的`backups/before-restore-*.json`，重新走预览/确认/屏障/安全副本/换代完整流程。未完成恢复可在设置页“接续未完成的恢复”，或`node scripts/technical-restore.mjs <实例根绝对路径> --resume`；普通项目启动也会接续。不可手工把activeRestoreId置空。

副本损坏且原数据不完整时保持暂停，需维护者取得校验匹配的安全副本；记录没有声称已经开放。旧结构DB缺列的技术文件先在独立环境升级后再导入，不能直接覆盖真实库。测试注入hooks仅供隔离单元测试，不通过HTTP、上传内容或环境变量开放。

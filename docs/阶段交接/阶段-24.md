## 快照与需求依据

`captureExportSnapshot(tx, tripId, expectedPlanVersion)`是后续格式复用的入口。只支持**当前已保存计划**；历史状态没有历史清单/执行快照，因此不把当前进度套到历史计划上。

同一SQLite交互事务读取Trip当前计划指针、PlanVersion全内容、当前需求的修订/确认修订、ChecklistState、ExecutionState、该计划EvidenceFact。日期、人数、预算、偏好来自PlanVersion自己的`requestSnapshot`，从不读取当前TripRequest内容来拼接。最新R或确认不匹配、或者plan.requirementUpToDate=false时，文件显式待更新。

清单通过`projectChecklist`从这次事务里的已存清单和计划/来源投影，不写清单、不自增清单修订；快照记录投影项、basis、revision、updatedAt。执行保存解析后的人工状态及revision。来源按生成时间计算有效状态。红线只用同一计划内的路线和票据，经既有算法计算；`cache:false`防止混入缓存结果，不调用网络。渲染阶段不得再查询实时需求/位置/路线/状态。

快照`schemaVersion:1`含`id/generatedAt/plan/latestRequestRevision/requirementUpToDate/checklist/execution/evidence/redlines`。其中`plan`完整保留自身R/requestSnapshot。快照JSON只在服务器数据库中保存，下载HTML没有任何原始JSON、票图、设置或执行定位点。服务只向浏览器返回文件元信息。

导出在同一事务里捕获、渲染并创建ExportFile，最后再次检查取消signal；失败回滚，不留下半成品。预计V不匹配409。取消后客户端重新读取记录，处理响应丢失导致“服务端已保存”的可能性。独立文件是不可变历史产物，不随后续需求/勾选/执行变化自动更新。

## 数据与接口

`ExportFile`字段：`id(UUID)/tripId/format(mobile-html)/planVersion/requestRevision/checklistRevision/executionRevision/requirementUpToDate/generatedAt/options/snapshot/filename/html/sha256`。HTML原文、快照和选项同表提交，避免文件系统/数据库分步失败；读取直接返回当时HTML，绝不重新渲染。SHA-256以UTF-8原文字节计算。

- `GET /api/trips/:id/exports`：`{plan:{versionNumber,requestRevision,dates}|null, files:ExportFileSummary[]}`。只列最近20份，但旧ID仍可读取，未实现自动清理。
- `POST`：`{expectedPlanVersion,options:{dates:null|string[],includePrivateAddress:boolean,includeSeats:boolean,publicLandmark:string}}`，2000字符上限。默认全部日期、两项隐私false、地标空；dates最多4个且须在计划日期中。UI支持全部/单日，服务器可接受多日子集。成功201 `{file}`。
- `GET /api/trips/:id/exports/:fileId`：inline静态HTML；`?download=1`返回attachment。两者字节一致、`text/html;charset=utf-8`、no-store、nosniff、no-referrer；HTTP CSP限定self frame-ancestors并启用sandbox。文件内meta CSP允许内联样式，其他资源默认禁用。不存在或跨旅行访问404。

文件名仅使用固定Serendipity前缀、计划日期、V和随机ID片段，不带住址/自由文本标题。删除旅行通过FK级联删除应用记录；应用不扫描用户下载目录。当前无导出记录单独删除界面。阶段28引入代际/恢复屏障时须把导出创建和旧页面请求一并接入，不能给旧快照临时补最新代际。

## HTML与隐私

静态结构：header版本/日期/人数/生成时刻/隐私提示 → 日期锚点导航 → 快速阅读/预算摘要 → 红线 → 各日独立section/活动列表 → 全局待确认 → 清单 → 打开说明。无脚本、外部字体、图片、地图、导航或来源链接；来源以文字名称/字段值/时间/适用日期保留。每个活动带日内编号、时间、地点、安排确认状态、已有交通、下一步、人工到达/完成记录。源资料可以用原生details展开，关键行动始终可见。

未选日期不生成其日程section，但跨到未选日期的下一步仍注明日期与“该日未选入本文件”。与所选票据或建议出发日期相关的红线保留，即使建议时刻在旅行前一天。预算明确为全程口径；不把未知金额算成0，也不将选一天误称单日预算。清单默认全部保留；单日包含该日/关联活动、无日期和出发前已到期准备事项，删除/失联的非相关系统项不带出。

默认隐私按去程票chainOriginName、返程票chainDestinationName、出行前/返家后活动、住宅特征及其关联Place识别私人地点，收集名称/地址，在所有输出文字中替换。关联私人路线不输出路线步骤、起点细节和可能反推位置的说明；保留原总耗时与红线。座位依据所有票据seat及常见车厢座位表达隐藏。所有输出文字统一HTML转义，并过滤URL、精细坐标、证件号及常见Key文本；不复制原始对象到HTML属性或注释。

勾选包含地址/座位仅带出对应文字，仍不包含定位坐标、几何、图片和链接。公共地标只是用户选择的附近辨认文字，**不能把该地标当成新路线起点或改写既有红线**。自由文本没有完美通用的语义隐私分类：当前采取已知起终点加保守住宅规则，并在生成后展示预览供用户选择保存的内容；已验证的泄露路径见核心测试。

执行状态只写“截至导出”，无倒计时或随时间变化的可行性。没有PWA、离线地图、离线AI、缓存同步或未来长图/PDF按钮。

## 当前体验

首页采用杂志封面布局，支持“实景 / 素描”双模式、“山河风物志”换景和样本弹窗。点击“开启旅程规划”后，保存、理解、补全、确认和生成连续完成；缺项或服务失败时保留已保存旅行，支持继续处理。画廊与样本用于启发，新旅行不受内置目的地限制。当前生成器支持2～4天，内置展示样本不代表生成器支持范围。

详情页以每日时间轴、伴随地图和预算看板为主，预算、票据、住宿等面板优先显示核心字段，高级接驳可折叠。390px头部已收紧；执行页沿用旅行短标题，并显示原话中明确的交通硬时刻。AI建议地点与已确认地点分别标示，坐标参考不等于已核验导航路线。

AI接入统一处理推理标签、Markdown包裹、注释、尾逗号、重复JSON编码及常见字段/金额格式差异；截断结果仍明确报错，时间、预算、版本和持久化校验继续执行。每天保留合理实质行程即可，不再强制每天凑准备节点、独立休息节点或返程两餐。泉州复测覆盖跨月周末、闭园时段、16:00返程、预算区间、坐标关联、雨天室内替代和票据接驳合并。

## 随身资料与调整

“PDF旅行手册”支持完整手册或简化资料、全部或单日、许可照片与隐私选项；核对隐私后即可生成、预览和下载A4多页PDF，**无需先逐一确认地点**。完整手册包含总览、每日地图和时间轴、预算、清单、提醒与来源；未确认的可用公开坐标以“AI建议 / 含待核实建议标点”进入示意图，无可用坐标时提示而不制造整页占位。泉州3日23节点完整PDF已从原25页压缩为10页并逐页检查。中文字体嵌入文件，可离线阅读；Windows Edge内嵌预览及断网阅读已验证，手机真机与实体打印尚未验证。

“旅行长图 · 保存图片”支持按日期生成PNG、完整预览、逐张下载和历史记录。包含时间轴、硬时刻、分类预算、清单及每日公开地点动线示意；AI建议点无需手动确认也可绘制。内容过长自动按天或段落分图，保存时收齐全部图片。私人地图标点始终省略。新环境可在 `npm ci` 后执行 `npx playwright install chromium` 安装渲染浏览器；Windows仅在缺少该可执行文件时回退已安装的Microsoft Edge，其它渲染错误仍明确失败。中文字体随依赖安装，无需联网加载。

计划和执行页提供“手机一页版 · 离线保存”：选择全部或单个日期、核对隐私选项，生成预览后下载独立HTML。保留计划版本、硬时刻、每日动线、分类预算、清单及导出时执行记录，支持跳日阅读。泉州文件已在Windows Edge的390px视口、file URL和断网条件下验证，无HTTP请求与横向溢出；Android/iOS真机文件打开方式仍待验收。

“文字导出 · 复制与下载”提供纯文字（.txt）与 Markdown（.md），复用同一导出快照。选择日期与隐私选项后生成，可复制全文、全选文字或下载 UTF-8 文件；剪贴板不可用时仍可取得完整内容。保留时间、地点、交通、红线、预算、清单、来源状态与版本；历史文件保持生成时内容，更新后需重新生成。文字导出不会自动向微信或其他应用发送消息。

四类导出读取同一版本快照，不会自动更新；旅行修改后需重新生成。默认隐藏私人住址和座位，公共交通枢纽名称及返程说明保留，包括与“家里”同时出现的“深圳北站”。地图为无道路底图的位置和顺序示意；有已保存且适用的天气预报时带入，超出预报窗口时如实提示，未知价格不会按零费用处理。

计划中的“AI 重新规划”可以用一句话调整剩余旅行，先比较移除项、新增替换项、时刻与预算变化，再确认应用。替换海边行程的雨天方案必须包含室内活动和必要接驳，不能只删不补；明确硬预算按已知费用区间上沿检查。系统保护有效票据、原话明确的交通硬时刻、已确定安排及费用；应用时重新检查当前时间，赶不上固定交通会拒绝，复核有实质变化则重新展示预览。候选可取消，最近一次调整可先预览再撤销；清单进度随统一计划版本保留。

## 启动

日常使用：打开桌面的 **“Serendipity 日常使用”** 文件夹，双击“启动旅行助手”。入口会自动检查源码：没有改动时复用现有版本，有改动时显示启动进度并自动构建、切换新版、打开网页；不再需要修改构建目录。应用正在运行时再次点击也会检查更新，点击前先保存当前编辑。构建失败会提示并保留可用版本；端口被占时自动选择空闲地址。“停止旅行助手”结束后台运行，“运行状态”查看状态和数据位置。关闭浏览器不会停止服务，重启电脑后再次双击启动即可，不设置自动开机运行。

当前[首页](http://127.0.0.1:3003)、[运行状态与数据位置](http://127.0.0.1:3003/runtime)。端口如变化，以启动器自动打开的网页为准。此地址只对本机有效；手机请提前保存文字、长图或 PDF，离线内容不会实时更新，也不能在线 AI 重规划。未部署个人外网实例。

维护者：桌面配置 `runtime/launcher.json` 已启用 `autoBuild: true`。启动器按源码内容、依赖清单和构建环境的指纹判断是否需要构建，自动选择 `.next-auto-...` 新目录，成功后只更新配置中的 `buildDirectory`。未提交文件、新增/删除文件也会被检测；文档、测试输出和 Next 自动生成的类型路径不会触发重复构建。失败保留旧产物，源码在编译期间变化时不启用该次产物。初次安装仍用 `scripts/windows/install-launcher.ps1 -BuildDirectory <已验证的初始构建>` 明确指定种子版本、原数据目录和端口；需要固定版本的维护实例可加 `-PinnedBuild`。日常代码修改无需重新安装入口。日志位于数据目录的 `runtime/build.log`，完整验证见[桌面启动自动更新](docs/阶段验收/桌面启动自动更新-2026-10-18.md)。不要覆盖运行中的构建，或另开手动实例访问同一数据库。

本项目已采用 Node.js 24、npm、Next.js、TypeScript、SQLite/Prisma。依赖使用 package-lock.json 固定；新环境安装使用 npm ci。

- 开发模式：npm run dev，默认回环地址 http://127.0.0.1:3000。
- 手动生产模式（维护用）：npm run build，然后 npm run start -- -p 3003；不与桌面启动器并行运行同一数据目录。
- 日常正式入口：http://127.0.0.1:3003/trips。

通过项目启动命令运行，不直接用 next start 代替受控启动器。默认仅本机访问，远程发布不属于当前交付范围。

## 数据与设置

设置页的“数据管理”支持下载格式1的JSON旅行备份。选择备份后先校验并显示旅行数与替换范围，勾选确认后恢复全部旅行；空备份会清空旅行列表。备份保留需求修订、计划历史/依据、必要票据及有效状态、费用、来源、清单和执行进度，不含服务密钥、会话、票据原图、运行代际或恢复屏障。导出缓存与待应用候选不打包，恢复后可重新生成导出。

恢复先持久暂停业务写入，在实例的 `backups/before-restore-*.json` 保存并核验安全副本，再原子替换旅行数据并换代。管理员与服务设置保留。失败保护/回退后也换代；未完成处理时保持暂停，设置页可接续，启动器也会检查未完成恢复。所有旧页面需完整重新载入后核对，不能直接重发原提交。普通重启保留代际。

技术恢复由维护者使用 `scripts/technical-restore.mjs`，明确指定目标实例与JSON/SQLite备份的绝对路径；第一次仅预览，带该摘要的确认值才执行。SQLite备份也只提取旅行表，走同一屏障、安全副本与换代协议，不覆盖数据库文件。不得用历史 `.db` 文件直接替换当前数据库或回退实例元数据。旧结构缺列的备份须先在独立环境升级后校验。

正式实例统一数据根目录为 **`C:/Users/user/SerendipityData`**：数据库在 `data/serendipity.db`，启动配置在 `runtime/launcher.json`，服务设置、密钥与运行资料沿用同一实例。2026-10-18启动修复已保全旧目录、数据库、设置和密钥，详见[修复记录](docs/阶段验收/桌面启动修复-2026-10-18.md)。手动运行 npm 命令时须显式将 `SERENDIPITY_DATA_DIR` 设为同一数据根目录；未指定时，开发脚本仍默认使用 LOCALAPPDATA/Serendipity，不能误当正式库。AI服务与密钥通过网页设置配置，勿把密钥放进聊天、Git或测试报告。

SERENDIPITY_DATA_DIR 可为隔离实例指定独立根目录，数据库位于该根目录的 data 子目录。正式数据和 test-data 必须分开；不要用真实旅行测试删除、恢复或迁移失败。

地图默认使用免费公共服务；手动公交参考保持待确认，不能视为自动未来班次或实时到站结果。

计划中的“出发前清单”按交通、住宿、预约、随身物品整理准备事项，支持勾选、自建、编辑、移出和恢复，手机有快捷入口。勾选只表示用户已自行确认，不执行购票、订房或预约。清单进度独立保存在本机；计划变化会保留仍相关的进度和自建内容，关联事项变化时提示重新核对。保存失败会保留原状态和输入，可重新读取或重试。

计划中的“住宿推荐”可比较当天活动、次日活动与返程站周边区域，搜索确认具体酒店，记录日期、房数和入住/寄存条件。连续住宿按每晚分别计费；确认酒店后重算进店与次晨离店路线。区域点仅供方位参考，酒店地点、预算估算和房态分别显示，应用不办理订房。

计划总览提供出门与返程红线，可展开每个截止、缓冲、建议时刻与当前时刻的检查，并保存行李 / 办理条件。原话明确给出的交通时刻即为规划硬约束，不必先录入车票；票据中只有有效票参与票面硬约束。接驳时长和缓冲仍按来源显示估算或待确认，不保证赶上。激活票据时会合并已有同类去站/候车节点，避免重复接驳与费用；非法出发/到达时序可在保存前原地更正。

门到门交通页可导入高铁票截图：选图、裁剪或旋转、查看本机 OCR 草稿，再核对确认。PNG/JPEG/WebP 单张不超过 10MB；只将所选区域发到本机服务，不调用第三方或使用 AI Key。识别模型随 npm 依赖安装，图片不落盘。重复、同行、指定替换及已退票事实均需明确选择，退款仍在预算中另行确认。

## 验证

- npm test：当前单元与集成回归，使用隔离测试数据。
- npm run typecheck：类型检查。
- npm run lint：静态检查。
- npm run test:e2e：生产构建与隔离浏览器验证，当前配置使用 Microsoft Edge 和独立 3100 端口。
- npm run verify:phase16：生成匿名合成票面，并实际运行本机 OCR 验证；常规单元测试默认跳过这一独立真实识别用例。
- npm run verify:ocr-offline：在服务、识别子进程和工作线程中拦截 Node 网络 API，运行真实本机 OCR；这是 API 层验证，不是操作系统级抓包。测试证据写入隔离 test-data/verification-output，不覆盖旧验收证据。

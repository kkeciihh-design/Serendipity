# Serendipity

个人本机使用的 AI 旅行规划工具。需求确认、计划版本、时间轴、预算、来源核验、地点地图、城市路线、门到门票据和时间红线的实际进度见 [开发进度](docs/开发进度.md)。

日常操作见[第一版使用说明](docs/第一版使用说明.md)。阶段30已完成本机修复、650项单元/集成和125项浏览器回归；整版仍为**外部条件待验收**，自动来源查询的人机验证与手机HTML真机缺口见[验收记录](docs/阶段验收/阶段-30.md)。

“PDF旅行手册”支持完整手册或简化资料、全部或单日、许可照片与隐私选项；确认后生成、预览和下载 A4 多页 PDF。完整手册包含封面、总览、每日地图和时间轴、景点/餐厅/住宿、预算、清单、提醒与来源；缺少必要地图或字体时明确失败。地图沿用已确认公开地点的位置示意，不含道路底图；中文字体嵌入文件，可离线阅读和打印。Windows Edge 内嵌预览及本地断网阅读已验证，手机真机与实体打印尚未验证。每份记录保留生成时的版本与内容，后续修改需重新生成；默认隐藏私人地址和座位。

“旅行长图 · 保存图片”支持按日期生成 PNG、完整预览、逐张下载和历史记录。包含时间轴、红线、预算、清单，可选已确认公开地点的位置示意图与许可照片；内容过长自动按天或段落分图，保存时收齐全部图片。示意图不含道路底图，私人地图标点始终省略。新环境在 `npm ci` 后执行 `npx playwright install chromium` 安装受控截图浏览器；中文字体随依赖安装，无需联网加载。

当前计划和执行页提供“手机一页版 · 离线保存”：选择全部或单个日期、核对隐私选项，生成预览后下载独立 HTML。默认隐藏私人起终点和座位，保留计划版本、时间红线、清单与导出时执行记录；文件不会自动更新。Windows Edge 本地断网阅读已验证，Android / iOS 真机文件打开方式仍待验收，阶段24尚未标为通过。

“文字导出 · 复制与下载”提供纯文字（.txt）与 Markdown（.md），复用同一导出快照。选择日期与隐私选项后生成，可复制全文、全选文字或下载 UTF-8 文件；剪贴板不可用时仍可取得完整内容。保留时间、地点、交通、红线、预算、清单、来源状态与版本；历史文件保持生成时内容，更新后需重新生成。文字导出不会自动向微信或其他应用发送消息。

计划中的“AI 重新规划”可以用一句话调整剩余旅行，先比较取消、替换、时刻与预算变化，再确认应用。系统保护有效票据、已确定安排及费用；应用时重新检查当前时间，赶不上固定交通会拒绝，复核有实质变化则重新展示预览。候选可取消，最近一次调整可先预览再撤销；清单进度随统一计划版本保留。

## 启动

日常使用：打开桌面的 **“Serendipity 日常使用”** 文件夹，双击“启动旅行助手”自动打开网页。重复启动会复用同一实例；端口被占时自动选择空闲地址。保存编辑后，双击“停止旅行助手”结束后台运行；“运行状态”可查看状态和数据位置。关闭浏览器不会停止服务，重启电脑后再次双击启动即可，不设置自动开机运行。

当前[首页](http://127.0.0.1:3003)、[运行状态与数据位置](http://127.0.0.1:3003/runtime)。端口如变化，以启动器自动打开的网页为准。此地址只对本机有效；手机请提前保存文字、长图或 PDF，离线内容不会实时更新，也不能在线 AI 重规划。未部署个人外网实例。

维护者：当前生产构建为 `.next-phase30-verified`，设置 `SERENDIPITY_BUILD_DIR=.next-phase30-verified` 后执行 `npm run build`。`scripts/windows/install-launcher.ps1` 安装当前 Windows 用户的三个快捷方式，并将实际应用路径、Node 路径、数据目录和首选端口保存在实例 `runtime/launcher.json`。桌面安装默认使用用户目录下的 `SerendipityData`，避免 Windows 应用包对 LocalAppData 的重定向；发现旧数据时会要求先保全并显式指定目录，不自动创建替代数据库。先停止再升级，见[阶段30交接](docs/阶段交接/阶段-30.md)。不要在运行时覆盖发布构建目录，或把不同正式启动器同时指向同一数据库。

本项目已采用 Node.js 24、npm、Next.js、TypeScript、SQLite/Prisma。依赖使用 package-lock.json 固定；新环境安装使用 npm ci。

- 开发模式：npm run dev，默认回环地址 http://127.0.0.1:3000。
- 手动生产模式（维护用）：npm run build，然后 npm run start -- -p 3003；不与桌面启动器并行运行同一数据目录。
- 日常正式入口：http://127.0.0.1:3003/trips。

通过项目启动命令运行，不直接用 next start 代替受控启动器。默认仅本机访问，远程发布不属于当前交付范围。

## 数据与设置

设置页的“数据管理”支持下载格式1的JSON旅行备份。选择备份后先校验并显示旅行数与替换范围，勾选确认后恢复全部旅行；空备份会清空旅行列表。备份保留需求修订、计划历史/依据、必要票据及有效状态、费用、来源、清单和执行进度，不含服务密钥、会话、票据原图、运行代际或恢复屏障。导出缓存与待应用候选不打包，恢复后可重新生成导出。

恢复先持久暂停业务写入，在实例的 `backups/before-restore-*.json` 保存并核验安全副本，再原子替换旅行数据并换代。管理员与服务设置保留。失败保护/回退后也换代；未完成处理时保持暂停，设置页可接续，启动器也会检查未完成恢复。所有旧页面需完整重新载入后核对，不能直接重发原提交。普通重启保留代际。

技术恢复由维护者使用 `scripts/technical-restore.mjs`，明确指定目标实例与JSON/SQLite备份的绝对路径；第一次仅预览，带该摘要的确认值才执行。SQLite备份也只提取旅行表，走同一屏障、安全副本与换代协议，不覆盖数据库文件。不得用历史 `.db` 文件直接替换当前数据库或回退实例元数据。旧结构缺列的备份须先在独立环境升级后校验。

当前桌面实例数据在 `C:/Users/user/SerendipityData/data/serendipity.db`，启动配置在同一根目录的 `runtime/launcher.json`。2026-10-18启动修复已保全旧目录、数据库、设置和密钥，详见[修复记录](docs/阶段验收/桌面启动修复-2026-10-18.md)。手动运行 npm 命令时须显式将 `SERENDIPITY_DATA_DIR` 设为同一数据根目录；未指定时，开发脚本仍默认使用 LOCALAPPDATA/Serendipity。AI 服务与密钥通过网页设置配置，勿把密钥放进聊天、Git 或测试报告。

SERENDIPITY_DATA_DIR 可为隔离实例指定独立根目录，数据库位于该根目录的 data 子目录。正式数据和 test-data 必须分开；不要用真实旅行测试删除、恢复或迁移失败。

地图默认使用免费公共服务；手动公交参考保持待确认，不能视为自动未来班次或实时到站结果。

计划中的“出发前清单”按交通、住宿、预约、随身物品整理准备事项，支持勾选、自建、编辑、移出和恢复，手机有快捷入口。勾选只表示用户已自行确认，不执行购票、订房或预约。清单进度独立保存在本机；计划变化会保留仍相关的进度和自建内容，关联事项变化时提示重新核对。保存失败会保留原状态和输入，可重新读取或重试。

计划中的“住宿推荐”可比较当天活动、次日活动与返程站周边区域，搜索确认具体酒店，记录日期、房数和入住/寄存条件。连续住宿按每晚分别计费；确认酒店后重算进店与次晨离店路线。区域点仅供方位参考，酒店地点、预算估算和房态分别显示，应用不办理订房。

计划总览提供出门与返程红线，可展开每个截止、缓冲、建议时刻与当前时刻的检查，并保存行李 / 办理条件。红线根据实际来源显示估算或待确认，不保证赶上；只有有效票据参与硬交通约束。

门到门交通页可导入高铁票截图：选图、裁剪或旋转、查看本机 OCR 草稿，再核对确认。PNG/JPEG/WebP 单张不超过 10MB；只将所选区域发到本机服务，不调用第三方或使用 AI Key。识别模型随 npm 依赖安装，图片不落盘。重复、同行、指定替换及已退票事实均需明确选择，退款仍在预算中另行确认。

## 验证

- npm test：当前单元与集成回归，使用隔离测试数据。
- npm run typecheck：类型检查。
- npm run lint：静态检查。
- npm run test:e2e：生产构建与隔离浏览器验证，当前配置使用 Microsoft Edge 和独立 3100 端口。
- npm run verify:phase16：生成匿名合成票面，并实际运行本机 OCR 验证；常规单元测试默认跳过这一独立真实识别用例。
- npm run verify:ocr-offline：在服务、识别子进程和工作线程中拦截 Node 网络 API，运行真实本机 OCR；这是 API 层验证，不是操作系统级抓包。测试证据写入隔离 test-data/verification-output，不覆盖旧验收证据。

旧阶段 03–10 的一次性验收/截图脚本已停用，不能用于当前版本；请使用上述现行回归入口。外部地图演示属于单独验证，必须显式启用并使用隔离实例，不等同于离线自动测试。
